Your biggest blocker is at the very top of that file: **`"engines": {"node": ">=18"}`**. Angular 20 dropped Node 18 entirely — it needs `^20.19.0 || ^22.12.0 || ^24.0.0` (note: odd majors like 21/23 aren't supported). Sort that out before anything else, including CI images and any `.nvmrc`/Dockerfile.

## 1. Prep

```bash
git checkout -b feat/angular-20
node -v                      # must be 20.19+ / 22.12+
npm ls @angular/core         # confirm you're clean on 19.2.x first
```

Also: temporarily disable your `patch-package` postinstall. `patches/primeng+19.1.4.patch` will hard-fail the moment PrimeNG's version changes, and you don't want that masking real errors mid-update.

## 2. Core update

`ng update` refuses to run with unmet peers, and you have two known offenders (`angular2-multiselect-dropdown` pinned to ancient Angular, `jest-preset-angular` 14.x). Same play as last time:

```bash
npx ng update @angular/core@20 @angular/cli@20 --force
npx ng update @angular/cdk@20 2>/dev/null   # skip if unused
```

Then update the rest of the Angular-versioned packages manually — `@angular-devkit/build-angular`, `@angular/compiler-cli`, `@angular/language-service`, and **`ng-packagr` to ^20.x** (must match the major, or the library build breaks).

Keep `typescript` at `~5.8.3` — that's exactly what v20 wants. `zone.js ~0.15.1` and `rxjs ^7.8.1` are already fine.

## 4. PrimeNG 20 — plan for real work

This is where most of your time goes:

- Theming moved from `@primeng/themes` to **`@primeuix/themes`** (you don't have the former listed, so check whether wings-front owns that config).
- The components deprecated in v19 are gone in v20: `p-dropdown` → `p-select`, `p-calendar` → `p-datepicker`, `p-inputSwitch` → `p-toggleswitch`, `p-overlayPanel` → `p-popover`, `p-sidebar` → `p-drawer`, `p-messages` → `p-message`, TabView → Tabs. Your AccordionTab migration already landed, so that one's paid off.
- Regenerate the patch: check first whether the `clearFilterValues()` type guard is still needed in 20.x. If it is, regenerate against the real 20.x tarball and keep `*.patch text eol=lf` in `.gitattributes` so it doesn't break on Git Bash again.

## 5. Library-specific (don't skip)

In `projects/ng-wings/package.json`: bump `peerDependencies` to `^20.0.0` and the version to `20.0.0`.

**Sequencing matters here.** A library built with ng-packagr 20 emits Angular 20 partial-Ivy output that an Angular 19 app *cannot* consume. So wings-front has to upgrade in lockstep — publish the v20 `ng-wings` to your internal registry only when wings-front's branch is ready to take it.

## 6. Expect these at build time

- `ng-reflect-*` attributes are gone in dev mode — any test asserting on them fails.
- `TestBed.flushEffects()` → `TestBed.tick()`.
- `platformBrowserDynamic()` is deprecated; `platformBrowser().bootstrapModule()` from `@angular/platform-browser` is the replacement. Deprecated, not removed, so it won't block you.
- `NgIf`/`NgFor`/`NgSwitch` are now soft-deprecated in favour of `@if`/`@for`. Optional, and `ng generate @angular/core:control-flow` will do it — but run it as a separate commit, not inside this one.

One last thing: v20 is in LTS now, not current. Doing 19→20 first is still correct (never skip a major), but budget for a follow-up.
