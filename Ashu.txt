# Task: fix table cell content overflowing into adjacent cells in the document-template PREVIEW

## Repo context
Angular (NgModule-based) app: wings-front. It contains a TinyMCE-based document
template editor plus a separate read-only PREVIEW that renders the parsed
template HTML. The editor renders correctly; only the preview is broken.

## Bug
In the preview, long unbreakable cell text (e.g. "G2506DE000628689" rendered from
a variable span) paints over the neighbouring cells instead of wrapping onto the
next line inside its own cell.

Sample of the parsed preview HTML (abridged):

<div data-rendered-preview="true"><div class="page" style="font-family: 'BNPP Sans'; height: 1503px;">
<table border="1" style="border-collapse: collapse; table-layout: fixed; width: 100.074%; ; width: 100%;" data-table-type="static"><colgroup>
<col style="width: 14.7437%;"><col style="width: 9.41085%;"> ... <col style="width: 2.82325%;"></colgroup>
<tbody><tr>
<td style="border: 0.995025px solid rgb(0, 0, 0);;  overflow-wrap: anywhere;"><span style="font-size: 4pt;">
<span class="variable noneditable" id="variableId-295" variable-id="295" format-type="string" group-name="References" transpose-type="exact">
{{Guarantee Id_References}} </span> </span></td>
</tr></tbody></table></div></div>

## Confirmed root causes (do not re-diagnose, fix these)
1. The <col> width percentages sum to ~100.38%, so the browser proportionally
   rescales every column and the defined widths are not honoured. The <table>
   also carries a duplicated width declaration ("width: 100.074%; ; width: 100%;").
2. The content has no usable break opportunity in the preview:
   - the wrap rules exist only in TinyMCE's content_css, which the preview does
     not load;
   - `.variable.noneditable` is styled as an inline-block chip, and an
     inline-block sizes to max-content, so `overflow-wrap` on the ancestor <td>
     cannot shrink it. Only `word-break: break-all` on the chip itself will.
   - `table-layout: fixed` + default `overflow: visible` on <td> +
     `border-collapse: collapse` means the overflow paints over the next cell.

## Step 3 — Normalize colgroup widths
Add this helper next to the existing table-serialization code (match the file's
existing naming and export conventions):

function normalizeColWidths(table: HTMLTableElement): void {
  const cols = Array.from(table.querySelectorAll('col'));
  const widths = cols.map(c => parseFloat(c.style.width) || 0);
  const sum = widths.reduce((a, b) => a + b, 0);
  if (!sum) return;
  const factor = 100 / sum;
  cols.forEach((col, i) => {
    col.style.width = `${+(widths[i] * factor).toFixed(4)}%`;
  });
  table.style.width = '100%';
  table.style.tableLayout = 'fixed';
}

Call it on every `table[data-table-type]` in BOTH places:
- when template HTML is saved/serialized from the editor
- when the preview renders the HTML
so the two paths produce identical numbers.
