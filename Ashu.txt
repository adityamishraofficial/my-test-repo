# Task
In the Angular app `wings-front`, move the "Dynamic Name" section so it renders
INSIDE the Template Editor card, directly above the TinyMCE editor, instead of
sitting in its own full-width container above it. Layout change only — no
behaviour changes, no API changes.

# Current state (from the Template Management > Create page)
- A standalone "Dynamic Name" container spans the full page width. It contains:
  a hint line, a chip field (variable chips + literal separator text), a
  "109 / 500 chars" counter, a "Hide Preview" toggle, a "RESOLVED PREVIEW" row,
  and a "43 / 200" counter on the right.
- Below it, a "Template Editor *" card holds a validation message
  ("Content is required"), the TinyMCE menubar/toolbar, and the editor canvas.
- To the right of the editor card sits a narrow rail with collapsible
  "Variables" and "Clauses" panels. Variables are dragged from this rail into
  both the Dynamic Name chip field and the editor.
- Below: a "Template Criteria" section, then a Preview / Submit / Cancel footer.

# Target state
The Template Editor card contains, in order:
1. Card header: "Template Editor *" + its validation message (unchanged)
2. A compact "Dynamic name" strip (label, chip field, counter row, collapsible
   resolved preview)
3. A hairline divider
4. The TinyMCE editor, unchanged

The old standalone Dynamic Name container is removed entirely. The strip now
occupies the editor column width only — it must NOT span under the right rail.

# Step 1 — Discover before editing
Do not edit anything yet. Locate and report:
- The component template containing the "Dynamic Name" label and
  "RESOLVED PREVIEW" text (search for the i18n keys, not the English strings —
  this project uses @ngx-translate).
- The component template containing the TinyMCE editor and the "Template Editor"

- How variables are dragged from the Variables rail into the chip field:
  Angular CDK (cdkDropList / cdkDropListConnectedTo / cdkDragData) or native

Print a short findings summary, then proceed.

# Step 2 — Move the markup
- If Dynamic Name is already its own component: relocate its selector tag into
  the editor card template. Do not modify the component's @Input/@Output
  signatures, selector, or internal logic.
- If it is inline markup: extract it into a new standalone-in-name-only
  component declared in the same NgModule (this project is NgModule-based, not
  standalone components), then place it in the editor card.
- The FormControl binding must keep working. If the control lives in a different
  FormGroup or component than the editor, pass it down via @Input or use
  formGroupName/formControlName consistent with how the rest of this form is
  wired. Do not introduce a new form or a second source of truth.
- Move all existing translate keys as-is. Do not hardcode English strings and do
  not invent new keys unless a new element genuinely needs one.

# Step 3 — Restyle for the narrower column
The strip is now roughly half its previous width, so:
- Chips must wrap onto multiple lines. The chip row grows from one line to a
  max-height of about three lines, then scrolls vertically. Never scroll
  horizontally.
- Long chip labels (e.g. "Underlying transaction details") truncate with
  text-overflow: ellipsis and expose the full label via title/tooltip.
- Put the char counter and the preview toggle on one right-aligned row below the
  chip field, not on separate lines.
- The resolved preview stays collapsible. Keep the existing Hide/Show Preview
  behaviour and its current default state. When expanded, the resolved value
  wraps (overflow-wrap: anywhere) instead of overflowing.
- Keep the strip visually secondary to the editor: smaller label, hairline
  separator below it, no heavy border or nested card.
- Write styles in the owning component's .scss using the project's existing
  Sass variables/mixins via @use. Do not add global styles, do not add new
  colour literals, do not introduce !important.
