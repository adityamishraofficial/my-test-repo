TASK: Diagnose and fix table column overflow in our TinyMCE template editor.

CONTEXT
- Angular (NgModule) app; TinyMCE wrapped in a template-editor component.
- Table cells contain variable tokens as spans, e.g.
  <span data-var="..." data-table-type="..." data-repeat="row">{{Base Amount_Amounts Currencies}}</span>
- Backend expands rows/variables and renders the saved HTML to PDF.

SYMPTOM
With 10-12 columns and a variable in every cell, columns overflow the page
width in BOTH the editor and the generated PDF. Near-zero-width leftover
columns appear at the right edge of the table.

STEP 1 - INVESTIGATE (report findings with file:line before changing code)
1. Locate the TinyMCE init config. Report current table_sizing_mode,
   table_column_resizing, table_default_styles, table_default_attributes,
   content_style.
2. Check whether px widths are written to table / colgroup / col / td / th
   and persisted into saved template HTML. Inspect one saved template.
3. Check the column-insert and "Iterate" code paths: do they redistribute
   widths, or append to the table total?
4. Check for stale <col> entries or trailing empty cells.
5. Check whether the PDF/render stylesheet mirrors the editor CSS.

STEP 2 - PROPOSE
- List all plausible causes, ranked by likelihood, each with evidence.
- Give two solution options with tradeoffs:
  (a) equal columns: table-layout: fixed + width: 100%
  (b) content-proportional: auto layout + overflow-wrap: anywhere
  Recommend one and say why.
- Propose a width-normalization routine that runs on table mutation
  (init/TableModified/NewCell/SetContent) and again before save, stripping
  width attributes/styles and stale colgroups.
- Propose page-level handling for 10-12 columns in the renderer
  (landscape, reduced font size).

CONSTRAINTS
- Do not change the span attribute contract (data-var, data-table-type,
  data-repeat, data-entity).
- Editor CSS and PDF CSS must stay in sync.
- Output a patch/diff per file. No unrelated refactors.
- Wait for my approval before applying changes.
