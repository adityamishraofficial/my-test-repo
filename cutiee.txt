# Angular 20 → 21 upgrade runbook — f-ng-wings-lib

All versions below were queried live from the npm registry on 1 Sep 2026. Nothing here is estimated.

---

## 0. Version reality check

| Train | Latest published |
|---|---|
| Angular 21 (your target) | **21.2.22** |
| Angular 22 | 22.1.4 — **not** your target |

Angular 21.0.0 shipped 2025-11-19; the 21.x line is mature.

**Critical:** `ng update @angular/core` with no version pin will jump you to 22. Always write `@angular/core@21`.

Package majors do **not** all track Angular. Verified ceilings for the Angular-21 line:

| Package | Angular-21-compatible max |
|---|---|
| `@angular/*` (core, common, forms, router, animations, compiler, platform-browser) | `21.2.22` |
| `@angular/cli`, `@angular-devkit/build-angular`, `@angular/build` | `21.2.22` |
| `@angular/cdk` | `21.2.14` (patch cadence differs from core — do not force 21.2.22) |
| `ng-packagr` | `21.2.7` |
| `@angular-eslint/*` | `21.4.0` |
| `primeng` | `21.1.9` (peer: `@angular/core ^21.0.7`) |
| `@primeuix/themes` | `^2.0.3` — **not 3.x** |
| `jest-preset-angular` | `17.0.0` |
| `typescript` | `~5.9.3` — **not 6.x** |

Node: `^20.19.0 || ^22.12.0 || >=24.0.0`. Check `node -v` before you start.

## 1. Hard blockers (these break `npm install` or the build)

**1. `jest-preset-angular@14.6.2` — install-level hard fail.**
Its peer range is `@angular/core >=15.0.0 <21.0.0`. It cannot coexist with Angular 21. Must go to `17.0.0` (peer `>=20.0.0 <23.0.0`), which forces:
- `jest` 29 → `^30.5.1` (jpa 17 peers `jest ^30.0.0`)
- `@types/jest` 29 → `^30.0.0`
- `jsdom >=26` as an explicit devDependency (peer requirement)
- `jest-environment-jsdom@^30.5.1` if you reference it in `jest.config`

**2. TypeScript ceiling is 5.9, not 6.0.**
- `@angular/compiler-cli@21` peers `typescript >=5.9 <6.1`
- `ng-packagr@21.2.7` peers `typescript >=5.9 <6.0` ← **the binding constraint, because this is a library**

So: `~5.9.3`. TS 6.0.3 is the Angular 22 step, not this one.

**3. `@fortawesome/angular-fontawesome@3.0.0` → `4.0.0`.**
v4.0.0 peers `@angular/core ^21.0.0`; v5.x peers `^22.0.0`. v4.0.0 depends on `@fortawesome/fontawesome-svg-core ^7.1.0`, so both FA icon packages move 6.5.2 → `^7.3.1`. **FontAwesome v7 renamed icons** — expect `far`/`fas` import breakage.

**4. `@primeuix/themes@1.2.5` → `^2.0.3`. Do not take 3.0.0.**
- `primeng@21.1.9` depends on `@primeuix/styled ^0.7.4`
- `@primeuix/themes@2.0.3` depends on `@primeuix/styled ^0.7.4` ✅
- `@primeuix/themes@3.0.0` depends on `@primeuix/styled ^1.0.0` ❌ (that's the PrimeNG 22 pairing)

Same logic for `primeicons`: stay on `^7.0.0`. `primeicons@8.0.0` was published the same day as themes 3.0.0 — it's the PrimeNG 22 era.

**5. `primeng` ships no `ng-update` schematics.** I checked the 21.1.9 manifest: no `ng-update` key. Every PrimeNG 20→21 change is manual. Budget time for this separately from the Angular bump.

**6. `@angular/platform-browser-dynamic@21.2.22` is published but flagged deprecated on npm:**
> "@angular/platform-browser-dynamic is deprecated. Use `@angular/platform-browser` instead."

Your module-based bootstrap needs to move (see §5). `platformBrowser()` is exported from `@angular/platform-browser@21` and returns a `PlatformRef`, so `.bootstrapModule()` works unchanged.

**Good news:** the legacy webpack `browser` builder still exists in `@angular-devkit/build-angular@21.2.22` and is not marked deprecated in its `builders.json`. Your showcase app can stay on webpack.

## 2. Sequencing

1. **f-ng-wings-lib** (this repo) → build → publish to the internal registry
2. **wings-front** → only after the library is published

The library's `peerDependencies` gate everything downstream, so this order is not optional.

## 3. Step-by-step

### Step 1 — Baseline

```bash
git checkout -b chore/angular-21
git status                     # must be clean
node -v                        # must satisfy ^20.19 || ^22.12 || >=24
npx ng version
```

### Step 2 — Park the PrimeNG patch before anything else

`patch-package` will fail against the new PrimeNG and can abort the install. Get it out of the way first:

```bash
mkdir -p .patches-parked
git mv patches/primeng+20.*.patch .patches-parked/ 2>/dev/null || mv patches/primeng+20.*.patch .patches-parked/
```

You'll regenerate it for `primeng+21.1.9` in Step 9. (Standing recommendation, unchanged: overriding `clear()` in the ng-wings table wrapper to sanitize filters upstream would end this per-major regeneration cycle for good.)

### Step 3 — The one big `ng update` call

`@angular-eslint` must be in the same command as core, or you get an unresolvable peer graph mid-update:

```bash
npx ng update \
  @angular/core@21 \
  @angular/cli@21 \
  @angular/cdk@21 \
  @angular-eslint/schematics@21
```

`@angular/cli@21`'s `packageGroup` pulls `@angular/build`, `@angular/ssr`, `@angular-devkit/*` to 21.2.22 automatically. `ng-packagr` is **not** in that group — bump it by hand in Step 4.

If it refuses over `jest-preset-angular`, that's blocker #1. Do Step 4 first, then re-run Step 3.

### Step 4 — Hand-bump everything `ng update` doesn't own

See §4 for the complete target `package.json` block. Then:

```bash
rm -rf node_modules package-lock.json
npm install --ignore-scripts
npm ls @angular/core @angular/cdk primeng typescript ng-packagr
```

`--ignore-scripts` skips `patch-package` on this pass. Drop it once Step 9 is done.

### Step 5 — Review what the migrations did

The v21 core collection declares these migrations:

| Migration | Optional? |
|---|---|
| `application-config-core` — moves `ApplicationConfig` import from `@angular/platform-browser` to `@angular/core` | no |
| `bootstrap-options-migration` — deprecated `bootstrapModule` options → providers | no |
| `router-last-successful-navigation` | no |
| `control-flow-migration` — rewrites templates to `@if` / `@for` / `@switch` | **not flagged optional in v21** (it *was* flagged optional in v20) |
| `router-current-navigation` | optional |
| `add-bootstrap-context-to-server-main` | no |

Plus from `@schematics/angular@21`:

| Migration | Optional? |
|---|---|
| `update-typescript-lib` — bumps tsconfig `lib` to es2022+ | no |
| `update-module-resolution` — sets `moduleResolution: "bundler"` | no |
| `remove-default-karma-config` | no |
| `use-application-builder` — webpack `browser` → esbuild `application` | optional, "recommended" |

**Two things to check on your diff immediately:**

```bash
git diff --stat
git diff -- '*.html'
```

- **Control flow rewrite.** If templates were rewritten and you don't want that in this PR, revert just those files (`git checkout -- 'src/**/*.html'`) and keep the rest. Doing the framework bump and a global template rewrite in one commit makes bisecting a nightmare.
- **`moduleResolution: "bundler"`.** This is your recurring biter: it breaks deep imports into packages that lack an `exports` map entry. Build immediately after and fix the deep imports, or temporarily hold `moduleResolution: "node"` in `tsconfig.json` and address it as a follow-up.

**Skip `use-application-builder`.** Your showcase app uses the legacy webpack `browser` builder; that builder is still supported in v21, and swapping the build system in the same PR as the framework bump is a bad trade.

### Step 6 — Library `peerDependencies` (easy to miss)

The screenshots show the **workspace** `package.json`. The library's own manifest — `projects/f-ng-wings-lib/package.json` — carries the peer range consumers resolve against:

```json
"peerDependencies": {
  "@angular/common": "^21.0.0",
  "@angular/core": "^21.0.0",
  "@angular/forms": "^21.0.0",
  "@angular/router": "^21.0.0",
  "@angular/cdk": "^21.0.0",
  "primeng": "^21.0.0",
  "rxjs": "^7.8.0"
}
```

If this still says `^20.0.0`, wings-front will resolve a contradictory graph after the bump. Also bump the library `version` for the internal publish.

### Step 7 — Bootstrap code changes

`main.ts` (showcase app):

```ts
// before
import { platformBrowserDynamic } from '@angular/platform-browser-dynamic';

platformBrowserDynamic()
  .bootstrapModule(AppModule)
  .catch(err => console.error(err));

// after
import { platformBrowser } from '@angular/platform-browser';

platformBrowser()
  .bootstrapModule(AppModule)
  .catch(err => console.error(err));
```

Then sweep the whole repo:

```bash
grep -rn "platform-browser-dynamic" --include="*.ts" .
```

Test setup files are the usual stragglers. Remove `@angular/platform-browser-dynamic` from `package.json` once the grep is clean.

If you pass bootstrap options (`ngZoneEventCoalescing`, `ngZoneRunCoalescing`), `bootstrap-options-migration` should have converted them to `provideZoneChangeDetection({...})` providers — verify it did.

### Step 8 — Jest 30 / jest-preset-angular 17

**`jest-preset-angular/setup-jest` no longer exists.** I confirmed against both tarballs: 14.6.2 ships `setup-jest.js`; 17.0.0 ships only `setup-env/zone` and `setup-env/zoneless`.

```ts
// setup-jest.ts — before
import 'jest-preset-angular/setup-jest';

// after (you are zone-based; zone.js is still in your deps)
import 'jest-preset-angular/setup-env/zone';
```

Also check:
- `ts-jest` is a *dependency* of jest-preset-angular 17. You can drop your explicit `ts-jest` devDependency, or keep it pinned at `^29.4.12` — do not try for a `ts-jest@30`, it doesn't exist.
- Any `testEnvironment: 'jsdom'` reference needs `jest-environment-jsdom@^30.5.1` installed.
- Jest 30 tightened `testMatch` and removed some deprecated globals config. Run the suite early; failures here are noisy but shallow.

```bash
npx jest --clearCache && npm test
```

### Step 9 — PrimeNG 21 pass, then regenerate the patch

```bash
npm run build:lib   # or your ng-packagr build script
```

Fix PrimeNG 21 API/selector fallout from the compiler errors, checking the PrimeNG 21 migration notes as you go. Once the app builds and runs:

```bash
# apply your clearFilterValues null/type-guard fix by hand in
# node_modules/primeng/fesm2022/primeng-table.mjs
npx patch-package primeng
git add patches/primeng+21.1.9.patch
```

Your `.gitattributes` should already carry `*.patch text eol=lf` — confirm it does before committing, or the CRLF drift will bite on the next machine.

Then a clean verification install with scripts enabled:

```bash
rm -rf node_modules && npm install
```

### Step 10 — Verify and publish

```bash
npx ng lint
npm test
npm run build:lib
npm run build            # showcase app
npm pack ./dist/f-ng-wings-lib   # inspect before publishing
```

Publish to the internal registry, then start wings-front against the new version.

### Rollback

```bash
git checkout . && git clean -fd
git checkout main && rm -rf node_modules && npm ci
```

## 6. Post-upgrade quick reference

| Symptom | Cause |
|---|---|
| `ERESOLVE` naming `jest-preset-angular` | still on 14.x, peer caps at `<21.0.0` |
| `TS2307` on a deep `node_modules` import | `moduleResolution: "bundler"` |
| `setup-jest` module not found | entry point removed in jpa 15+ |
| Theme tokens render wrong / undefined | `@primeuix/themes` on 1.x or 3.x instead of 2.x |
| `ng update` landed you on 22.x | version pin omitted from the command |
| `patch-package` fails on install | patch still named `primeng+20.*.patch` |
| ng-packagr rejects your TypeScript | you went to 6.0.x; ng-packagr@21 caps at `<6.0` |
