# Role

You are a Senior Angular, TypeScript, and TinyMCE architect with expertise in building reusable, production-grade UI components and performing safe large-scale refactoring.

# Objective

I have discarded all previous changes and want to implement the reusable TinyMCE editor from scratch.

Currently, there are two separate TinyMCE implementations:

- Clause Management
- Template Management

Both implementations are stable and contain several custom features.

Your task is to create a single reusable TinyMCE editor component that can be used by both modules without changing any existing behavior.

The final implementation must be clean, maintainable, configurable, and fully backward compatible.

---

# Important Rules

Do NOT rewrite the application.

Do NOT simplify existing functionality.

Do NOT remove any feature.

Do NOT introduce breaking changes.

Do NOT hardcode module-specific logic inside the reusable component.

Keep the reusable component generic and configurable.

Preserve existing APIs wherever possible.

---

# Phase 1 – Analyze Existing Implementations

Before writing any code:

1. Analyze the complete TinyMCE implementation used in Clause Management.
2. Analyze the complete TinyMCE implementation used in Template Management.
3. Compare both implementations.
4. Identify:
   - Common functionality
   - Module-specific functionality
   - Shared configuration
   - Custom plugins
   - Custom toolbar buttons
   - Custom event handlers
   - Variable insertion logic
   - Placeholder handling
   - Continue Numbered List feature
   - Nested list handling
   - Custom commands
   - Image/File upload
   - Context menu
   - Keyboard shortcuts
   - Editor lifecycle handling
   - Validation
   - Read-only behavior
   - Editor initialization
   - Content loading
   - Content saving
   - Any differences between the two implementations

Do not start refactoring until the complete analysis is finished.

---

# Phase 2 – Design the Reusable Component

Create a reusable TinyMCE component that supports configuration through @Input() and emits events through @Output().

The component should expose configurable options instead of embedding business logic.

Examples include:

- Initial content
- Editor configuration
- Toolbar
- Plugins
- Height
- Read-only mode
- Placeholder
- Variable configuration
- Custom buttons
- Upload handlers
- Event callbacks

Avoid duplication while keeping the component generic.

---

# Phase 3 – Refactor

Replace the existing TinyMCE implementations in:

- Clause Management
- Template Management

Both modules must use the new reusable component.

Remove duplicate code only after confirming that the reusable component provides identical behavior.
