Multi-Client Architecture (Mandatory Requirement) This application must be designed as a single local AI platform that can be accessed from both: 1. A modern browser-based ChatGPT-style web application. 2. The Roo Code VS Code extension. Both clients must use the same local backend and the same GLM-5.2 model. Primary Goal Implement a single local AI server that exposes an OpenAI-compatible API. The browser UI and Roo Code must communicate with this server simultaneously. There must never be duplicate business logic. The backend is the single source of truth. Client 1 - Browser Application Develop a ChatGPT/Claude-style web application with: * Chat interface * Conversation history * Markdown rendering * Syntax highlighting * Streaming responses * Code blocks * Mermaid diagrams * LaTeX rendering * File uploads * Drag-and-drop * Project explorer * Monaco Editor * Integrated terminal * Diff viewer * Multi-tab workspace * Dark and light themes * Responsive UI * Session management * Local authentication (optional) * Settings page * Model management * Prompt library * Agent mode * Workspace management The browser should communicate exclusively with the local backend. No external APIs may be used. ⸻ Client 2 - Roo Code Integration The backend must be fully compatible with the Roo Code extension. The user should simply configure Roo Code to point to the local server. Example: Base URL: http://localhost:8000/v1 API Key: Any placeholder value accepted by the local server (or configurable authentication). The backend must support: * Streaming * Chat Completions * Tool Calling * Function Calling * JSON Responses * Long Context * Multi-turn Conversations * Code Generation * Code Editing * Repository Analysis * Repository Refactoring No adapters or modifications to Roo Code should be required. ⸻ Shared Backend The backend must be shared by both the browser application and Roo Code. Responsibilities include: * Prompt construction * Conversation memory * Context management * Model inference * Tool execution * File system access * Workspace indexing * Repository search * Agent orchestration * Streaming * Settings * Authentication (if enabled) Business logic must exist only once. ⸻ OpenAI-Compatible API Expose the following endpoints: * GET /v1/models * POST /v1/chat/completions * POST /v1/completions * POST /v1/embeddings (future support) * POST /v1/responses (future support) * GET /health * GET /version The response format must be fully compatible with the OpenAI API so Roo Code can connect without changes. ⸻ Local-Only Operation Everything must run locally. No cloud services. No OpenAI. No Anthropic. No Google. No Azure. No telemetry. No analytics. No external inference. No user code should ever leave the local machine. ⸻ Extensible Model Architecture Implement a provider abstraction so additional local models can be added easily. Initially implement GLM-5.2. The architecture should also support: * Qwen3-Coder * Qwen2.5-Coder * DeepSeek Coder * Devstral * Llama * Gemma * Phi The active model should be selectable at runtime without code changes. ⸻ Final Deliverable The completed project should function as a self-hosted AI coding platform that combines the capabilities of: * ChatGPT (browser interface) * Claude Code (coding workflows) * Roo Code (VS Code integration) * Cursor (AI-assisted development) All powered by a single local GLM-5.2 backend, accessible from both a browser and the Roo Code extension, with zero external dependencies after installation.
